# IRIS Common Library

Shared utilities and integrations for IRIS/Tu-GROW services. Everything is auto-configured by Spring Boot: add the dependency, set a few properties, and use it.

| Module | What it does |
|---|---|
| [Notification Client SDK](#notification-client-sdk) | Send notifications through the **notification-engine** (sync or async). |
| [Reference Generator](#reference-generator) | Short, human-readable, collision-free reference numbers (`ABQP30TZZC`) for receipts, invoices, orders and more. Built for 1B+ a day. |
| [Utilities](#utilities) | `UuidGenerator` (time-ordered UUID v7) and `ReadableFormat` (make any compact string easy to read). |

## Requirements

- Java 21+
- Spring Boot 3.2+

## Installation

Add the dependency to your `pom.xml`:

```xml
<dependency>
   <groupId>com.Tu-GROW.common</groupId>
   <artifactId>lib</artifactId>
   <version>1.0.7</version>
</dependency>
```

The library is hosted on GitHub Packages. Add the repository to your `pom.xml`:

```xml
<repositories>
   <repository>
      <id>github</id>
      <url>https://maven.pkg.github.com/Tu-GROW/common-lib</url>
   </repository>
</repositories>
```

And add your credentials to `~/.m2/settings.xml`:

```xml
<servers>
   <server>
      <id>github</id>
      <username>YOUR_GITHUB_USERNAME</username>
      <password>YOUR_GITHUB_TOKEN</password>
   </server>
</servers>
```

## Notification Client SDK

A lightweight SDK for sending notifications via the **notification-engine**. Add your config, extend one class, and start sending.

### Configuration

Add the following to your `application.yaml`:

```yaml
notification:
   client:
      # Required
      base-url: https://notification-engine.internal

      # Optional: SYNC (default) or ASYNC
      mode: SYNC

      # Optional: defaults shown
      uri: /notifications
      connect-timeout: 2s
      read-timeout: 5s

      # Optional: sent on every request
      default-headers:
         x-api-key: your-api-key-here
         x-source-system: my-service

      # Optional: retry on server errors
      retry:
         enabled: true       # default: true
         max-attempts: 3     # default: 3
         backoff: 300ms      # default: 300ms
```

`SYNC` uses a blocking HTTP client. `ASYNC` uses a non-blocking client and requires `spring-boot-starter-webflux` on the classpath. If `base-url` is not set the SDK does not activate.

### Usage

Extend `Notification` and add one method per notification scenario. Each method builds a `NotificationEvent` and calls `send()`, which is the only call site for sending notifications.

```java
@Service
public class NotificationService extends Notification {

   public Mono<NotificationEventResponse> sendOtp(String recipientId, String phone, String otp, String correlationId) {
      return send(NotificationEvent.builder()
              .eventId(UuidGenerator.generateV7())
              .channel(Channel.SMS)
              .recipientId(recipientId)
              .recipientRef(phone)
              .templateId("otp-verification")
              .templateData(Map.of("otp", otp))
              .priority(Priority.HIGH)
              .correlationId(correlationId)
              .build());
   }

   public Mono<NotificationEventResponse> sendWelcomeEmail(String recipientId, String email, String name, String correlationId) {
      return send(NotificationEvent.builder()
              .eventId(UuidGenerator.generateV7())
              .channel(Channel.EMAIL)
              .recipientId(recipientId)
              .recipientRef(email)
              .templateId("welcome-email")
              .templateData(Map.of("name", name))
              .priority(Priority.NORMAL)
              .correlationId(correlationId)
              .build());
   }
}
```

To pass per-request headers (for example an idempotency key), use the overload:

```java
return send(event, Map.of("x-idempotency-key", UuidGenerator.generateV7().toString()));
```

### NotificationEvent fields

| Field | Type | Required | Description |
|---|---|---|---|
| `eventId` | `UUID` | No | Idempotency key (RFC 9562 UUID v7, time-ordered). Auto-generated by the engine if omitted |
| `channel` | `Channel` | Yes | `EMAIL`, `SMS`, `WHATSAPP`, `IN_APP`, `PUSH`, `WEBHOOK`, `ALL` |
| `recipientId` | `String` | No | Internal user ID |
| `recipientRef` | `String` | No | External reference (email address, phone number, etc.) |
| `recipientIds` | `List<String>` | No | For bulk sends |
| `templateId` | `String` | Yes | Template identifier registered in the notification-engine |
| `templateData` | `Map<String, Object>` | No | Variables injected into the template |
| `priority` | `Priority` | No | `HIGH`, `NORMAL`, `LOW`. Defaults to `NORMAL` |
| `scheduledAt` | `Instant` | No | Future delivery time. Immediate if omitted |
| `tenantId` | `String` | No | For multi-tenant deployments |
| `correlationId` | `String` | No | Passed through for tracing |
| `metadata` | `Map<String, String>` | No | Arbitrary key-value pairs |

### Error handling

| Exception | When thrown |
|---|---|
| `NotificationClientException` | 4xx response: bad request, not retried |
| `NotificationServerException` | 5xx or network failure: retried per `retry` config |

```java
notificationService.sendOtp(recipientId, phone, otp, correlationId)
        .doOnError(NotificationClientException.class, e ->
        log.error("Invalid notification [{}]: {}", e.getStatus(), e.getBody()))
        .doOnError(NotificationServerException.class, e ->
        log.error("Notification engine unavailable: {}", e.getMessage()))
        .subscribe();
```

### Dynamic headers

To inject headers on every request (for example a trace ID from MDC), implement `NotificationHeaderProvider` and register it as a Spring bean:

```java
@Component
public class CorrelationHeaderProvider implements NotificationHeaderProvider {

   @Override
   public Map<String, String> resolve(NotificationEvent event) {
      return Map.of("x-correlation-id", MDC.get("requestId"));
   }
}
```

Multiple providers are supported and applied in `@Order` order.

## Reference Generator

Short, human-readable, collision-free reference numbers (M-Pesa style, for example `ABQP30TZZC`) for any entity: receipts, invoices, orders, payments. Built for 1B+ a day.

```
[year][month][day][7 chars = keyed permutation of the day's counter]

ABQP30TZZC     10 characters
ABQP30TZZC7    11 characters with the optional check character
```

- The date is UTC. The year character covers 2016 to 2047.
- The alphabet is Crockford base32 (no `I`, `L`, `O`, `U`), so refs are easy to read aloud and type.
- **Uniqueness:** a durable allocator leases disjoint counter blocks per UTC day, and a keyed Feistel bijection hides the sequence. Distinct counters always give distinct refs.

### Quick start

1. Create the counter table once (add it to your migrations):

   ```sql
   CREATE TABLE IF NOT EXISTS ref_counters (
       day        DATE   PRIMARY KEY,
       next_value BIGINT NOT NULL DEFAULT 0
   );
   ```

2. Set the master key (base64, at least 32 bytes, **the same on every instance**):

   ```yaml
   refgen:
     master-key: ${REF_MASTER_KEY}
   ```

3. Inject the generator, or annotate a field (next section):

   ```java
   @Autowired RefGenerator refs;

   String ref = refs.next();     // ABQP30TZZC
   ```

### Annotating entity fields

Annotate any `String` field and the ref is injected on insert, **only when the field is null**. A value you set yourself is never overwritten, and no counter value is used.

```java
@Entity
public class Receipt {
   @Id @GeneratedValue
   private Long id;

   @Reference(prefix = "RC-", display = RefDisplay.FORMATTED)
   @Column(name = "receipt_ref", length = 20, updatable = false, unique = true)
   private String receiptRef;          // stored: RC-ABQP30TZZC
}
```

| Attribute | Default | Effect |
|---|---|---|
| `prefix` | `""` | Text before the ref: `RC-ABQP30TZZC` |
| `suffix` | `""` | Text after the ref: `INV-ABQP30TZZC-KE` (with `prefix = "INV-"`) |
| `display` | `COMPACT` | `FORMATTED` shows the field grouped through `RefFormat` (see below). Never changes what is stored |

```java
@Reference                                                    // ABQP30TZZC
@Reference(prefix = "RC-")                                    // RC-ABQP30TZZC
@Reference(prefix = "INV-", suffix = "-KE")                   // INV-ABQP30TZZC-KE
@Reference(prefix = "RC-", display = RefDisplay.FORMATTED)    // stored RC-ABQP30TZZC, shown RC-ABQ-P30T-ZZC
```

- **Storage is always compact.** Size the column for prefix + suffix + 10 characters (11 with `check-char`).
- An entity can have several `@Reference` fields, each with its own prefix and suffix. Each gets a different ref.
- **Insert only.** Updates never touch the ref, so a partial update without it keeps the stored value.
- **JPA:** a Hibernate interceptor does the injection, with no `@EntityListeners` and no extra libraries. It runs alongside any interceptor you already configure. Turn it off with `refgen.inject-jpa=false`.
- **Spring Data JDBC:** a before-convert callback injects into new aggregates only. It is registered automatically when Spring Data JDBC is present.
- **Manual:** call `refInjector.inject(entity)` to fill null fields yourself (for example with `JdbcTemplate`).
- The field must be a non-final, non-static `String`. Records and other immutable entities cannot use it.

### Showing and looking up refs

Store the compact value; format it only for people. `RefFormat` is the ref-specific layer (prefix and suffix aware, validates input on the way back in):

```java
RefFormat.display("ABQP30TZZC");                                // ABQ-P30T-ZZC
RefFormat.display("ABQP30TZZC7");                               // ABQ-P30T-ZZC-7  (check character kept separate)
RefFormat.display("ABQP30TZZC", " ");                           // ABQ P30T ZZC

// field-aware: keeps prefix/suffix, groups only fields marked display = FORMATTED
RefFormat.display(Receipt.class, "receiptRef", receipt.getReceiptRef());   // RC-ABQ-P30T-ZZC

// what a person typed -> the stored value, or null if it is not a valid ref
String key = RefFormat.toStored(Receipt.class, "receiptRef", userInput);
```

A stored value that lacks the field's prefix or suffix (for example a row saved before the prefix was added) is still grouped when it is a bare 10/11-character ref; no affixes are added to it.

`toStored` accepts lower case, spaces or dashes, `O` for `0`, `I`/`L` for `1`, and an omitted prefix or suffix. It also rejects an impossible date or a wrong check character. Always look up with its result rather than raw input:

```java
String key = RefFormat.toStored(Receipt.class, "receiptRef", userInput);
if (key == null) {
        // not a valid ref: no database call needed
        }
```

Other helpers on `RefGenerator`: `isValid(input, hasCheckChar)`, `normalize(input)` and `dateOf(ref)` (the UTC issue date, for example to pick a partition).

### Configuration

| Property | Default | Description |
|---|---|---|
| `refgen.master-key` | none (required) | Base64, at least 32 bytes. Must be identical on every instance |
| `refgen.allocator` | `jdbc` | Where counter blocks are leased: `jdbc` or `jpa` (see below) |
| `refgen.block-size` | `1000000` | Counter values reserved per database round trip |
| `refgen.check-char` | `false` | Append an 11th check character that catches typos offline |
| `refgen.blocklist` | `SEX, ASS, KKK, HIV, TIT` | Substrings to skip. Setting it replaces the default list |
| `refgen.inject-jpa` | `true` | Auto-inject `@Reference` fields through Hibernate |
| `refgen.enabled` | `true` | Set `false` to switch the whole feature off |

Declare your own `RefGenerator`, `RefInjector` or `BlockAllocator` bean to override the defaults.

#### Choosing the allocator

- **`jdbc` (default):** leases blocks over its own autocommit connection from the `DataSource` pool.
- **`jpa`:** leases through your `JpaTransactionManager`, in its own `REQUIRES_NEW` transaction on the app's `EntityManagerFactory`. Use it if your `DataSource` is not directly injectable (for example multi-tenant routing).

Either way the lease commits independently of your business transaction. If it joined that transaction, a rollback would rewind the counter and the same range could be leased twice. Keep the connection pool larger than your peak concurrent transactions, because a lease needs a second connection.

#### Block size

A pod reserves `block-size` counter values in one database call, then issues refs locally with no database access. At 20% remaining it leases the next block in the background. Larger blocks mean fewer database calls and more tolerance of a database outage; a restart loses the unused part of a block, which is harmless (refs are unique, not gapless). The default suits roughly 1B refs a day.

### Operating rules

- **Same master key everywhere.** Every instance sharing a counter store must use the same key. Store it in your secret store, not in `application.yaml` or git. Rotate it only at a UTC day boundary with all instances restarted together.
- **The counter store must never go backwards.** Use synchronous commit with a synchronous standby (or a Raft-backed store), and never edit `ref_counters` by hand. A rewind can lease ranges that were already used.
- **A duplicate-key error is an incident.** Do not retry with a new ref. It means the allocator or key setup broke.
- **Add a unique index** on every ref column as the last line of defence.
- **Refs are immutable after insert.** `db/example/receipts.sql` shows a trigger that enforces it.
- **One generator, one counter stream.** All entities share it, so refs never collide across entity types. Do not create a generator per request.
- **Refs are identifiers, not secrets.** Do not use a ref alone as an access credential.
- **Year window.** Issuing stops at 00:00 UTC on 1 January 2048 (it fails closed and never duplicates). Plan the move to a longer format well before then.

`src/example` and `db/example` are illustrative and not part of the build.

## Utilities

### UuidGenerator

`com.iris.common.lib.utils.UuidGenerator` generates RFC 9562 UUID version 7 identifiers. They are time-ordered (they embed a 48-bit millisecond timestamp), unlike the fully random UUID v4 produced by `UUID.randomUUID()`. Use it wherever a new UUID is generated in application code (entity IDs, request IDs, idempotency keys, etc.) instead of `UUID.randomUUID()`, so identifiers sort by creation time and improve database index locality.

Backed by JUG (`com.fasterxml.uuid:java-uuid-generator`), which also guarantees monotonic ordering for UUIDs generated within the same millisecond.

```java
UUID id = UuidGenerator.generateV7();
```

### ReadableFormat

A general utility that makes any compact string easy to read, say aloud and type: phone numbers, card numbers, account numbers, big numbers, licence keys. It knows nothing about refs. Instances are immutable and thread-safe.

```java
ReadableFormat.groups(3, 4, 3).apply("ABQP30TZZC");                  // ABQ-P30T-ZZC
ReadableFormat.every(4).separator(" ").apply("4111111111111111");    // 4111 1111 1111 1111
ReadableFormat.every(3).separator(",").fromEnd().apply("1234567");   // 1,234,567
ReadableFormat.groups(4, 3, 3).separator(" ").apply("0712345678");   // 0712 345 678
ReadableFormat.groups(3, 4, 3).upperCase().apply("abqp30tzzc");      // ABQ-P30T-ZZC
```

| Method | Effect |
|---|---|
| `groups(int...)` | Explicit group sizes in order. Leftover characters form one final group; unused sizes are skipped when the value runs out |
| `every(int)` | Uniform groups; the last group holds the remainder |
| `separator(String)` | Any string, including empty or multi-character. Default `-` |
| `fromEnd()` | Group from the right, so the remainder lands at the front |
| `upperCase()` / `lowerCase()` | Convert case when applying or stripping |
| `apply(String)` | The readable form. Null returns null |
| `strip(String)` | Reverse: drops whitespace and the separator characters, so you can compare what a person typed |

```java
var card = ReadableFormat.every(4).separator(" ");
card.strip("4111 1111 1111 1111");      // 4111111111111111
```

`ReadableFormat` only changes how a value looks; it does not validate it. For anything with a check digit or a fixed alphabet, validate after `strip`. For references, use `RefFormat`, which adds prefix and suffix handling and validation.
